# UOSBuddy launch audit

Audited 25 Nov 2026 against sections 1–7 of `docs/UOSBuddy Launch Checklist & Runbook.md` (the
checklist's own prompt calls it `docs/LAUNCH_CHECKLIST.md`; the content is the same). Code at
`main` 897c5a2. No code was changed.

**Status key:** Done · Partly · Missing · Manual (needs the live system; the "Fix" column says
exactly what to look at). **Effort:** S = under half a day, M = 1–2 days, L = 3+ days.

**Stack note:** there is no FastAPI service any more. It was removed in PR #54 (`apps/ai` holds
only untracked leftovers); AI runs inside the Next.js app (`apps/web/lib/ai/`). FastAPI items are
marked N/A.

## Key findings

- **No secrets in the browser bundle.** A fresh production build of `main` was searched for the
  value of every variable in `apps/web/.env.local`. The service_role key, SMTP password, Turnstile
  secret and Upstash token appear nowhere in `.next/static` or in the server-rendered pages. The
  only matches are public values (`NEXT_PUBLIC_*`; `SMTP_USER` is the same address as the public
  support email). The word `service_role` appears in 0 client files. The VAPID private key and
  Anthropic key aren't set locally, so they couldn't be checked by value; both are read only in
  `server-only` files.
- **Security and privacy are the strongest area:** RLS on every table, enforced by a test; the
  privacy rules are tested in the database; rate limits are in place; export and delete have an
  end-to-end test.
- **The biggest gaps are operational:** the timetable isn't cached or available offline, pushes
  aren't batched, there's only one feature flag, there's no "Report wrong info", load tests skip
  the timetable, and monitoring/backups aren't confirmed on the live system.
